# FE4 鬥技場成長異常修正 — 升級時的 NMI／Direct Page 競態錯誤

[English](README.md) | **中文**

《火焰之紋章 聖戰系譜》（SFC，1996）的錯誤修正補丁。

玩家社群一直流傳「**在鬥技場升級，成長比較差**」。這是真的，而且是程式錯誤：升級程式和 NMI（垂直空白中斷）處理程式之間有競態條件。本補丁修正這個錯誤。

## 錯誤

升級時，計算神器血統成長加成的程式 `$84:A649` 會對 13 種血統迴圈，把累積值放在 Direct Page `$02`；內部呼叫的 `$84:A5C0` 用 `$00`。

NMI 處理程式入口（`$80:81B6`）會先把 D 設成 0，同樣以 `$00–$03` 為暫存，而且不一定會還原。NMI 若在 `$84:A649` 執行中途發生，算到一半的總和就會被覆寫：

```
NMI 前   $02 = 0000            （正確的中間值）
NMI 後   $02 = E1D0（−7728）   （NMI 自己的暫存值）
＋奧德 +20  $02 = E1E4（−7708）→ 成長率被夾成 0%，該項能力不成長
```

以上是在 snes9x 中用除錯版 ROM 捕捉到的實際數值：霍林的 HP 成長率 90% ＋ 傍系奧德 +20%，本應為 110%、必定成長，結果 HP 沒有成長。

- 地圖戰鬥的升級通常在一幀內完成，很少碰上。
- 鬥技場中主執行緒可用時間很少，升級橫跨約 3 幀，8 項成長率的計算都可能被打斷。
- **所有角色都會受影響**，不論有沒有血統：`$84:A649` 一律先清空 `$02`、跑完迴圈、回傳 `$02`。
- 錯誤存在於日文原版；保留這段程式的漢化版也一樣有。

## 結果

161 場打贏的鬥技場戰鬥（霍林，第二章），在 snes9x 中逐幀重播，各欄只有升級那一刻不同。正常基準是在同一記憶體狀態下、不含 NMI，直接執行升級程式 2,000 次的結果。

| 能力 | 原版 | 修正後 | 正常基準 |
|---|---|---|---|
| HP | 100% | 100% | 100% |
| 力量 | 31% | 34% | 32% |
| 魔力 | 3% | 6% | 6% |
| 技巧 | 72% | 80% | 80% |
| 速度 | 26% | 27% | 31% |
| 守備 | **11%** | 30% | 31% |
| 魔防 | 4% | 5% | 5% |
| 幸運 | 16% | 16% | 21% |
| 平均每級成長項數 | 2.63 | 2.98 | 3.05 |

原版的守備比基準低約 5.4 個標準誤，遠超一般抽樣波動；技巧低約 2.4 個標準誤，也呈現偏低趨勢，方向一致。修正後，各項成長率回到正常基準附近。力量略高於基準（34% 對 32%），但沒有出現各項普遍偏高的現象，比較符合恢復原本計算，而非單純提高成長率。

在固定亂數、不含 NMI 的環境中，修正前後的計算結果逐項相同（中文版 500 次、日文原版 300 次）。

## 修正方式

讓 `$84:A649` 在執行期間使用私有的 Direct Page：進入時在堆疊上預留 16 個位元組並令 D = S+1，離開時還原 D 與堆疊。

- NMI 以 D = 0 寫入 `$0000–$0003`：該位址已不是升級的暫存。
- NMI 的 push 只寫在 S 以下：預留區在 S 以上。

| SNES 位址 | 檔案位址（不含檔頭） | 原本 | 改為 |
|---|---|---|---|
| `$84:A649` | `0x04A649` | `8B 08 4B AB` | `5C A0 FF 86`（JML 入口） |
| `$84:A69A` | `0x04A69A` | `7A FA 28 AB` | `5C B7 FF 86`（JML 出口） |
| `$86:FFA0–FFC5` | `0x06FFA0` | 全為 `00`（未使用） | 38 位元組的入口／出口程式 |
| 標頭校驗和 | `0x00FFDC` | — | 重新計算 |

入口／出口程式的完整註解原始碼見 [`fe4_growth_race_fix.py`](fe4_growth_race_fix.py)。

## 套用方式

**請自備 ROM。本儲存庫不含任何 ROM 內容。**

| ROM | 識別 | 使用 |
|---|---|---|
| 日文原版 | 4 MB HiROM，標題 `FIREEMBLEM4`，無檔頭 CRC32 `DC0D8CF9` | 用任何 IPS 工具套用 `fe4_growth_race_fix_jp.ips`，套用後 CRC32 `CE39F90C` |
| 中文漢化版（火花天龍劍 V1.1） | `0052.SMC`，含 512 字節檔頭，無檔頭 CRC32 `C16D614E` | `fe4_growth_race_fix.py` |
| 其他版本、已打過其他補丁的 ROM | — | `fe4_growth_race_fix.py` |

```
python3 fe4_growth_race_fix.py 輸入.sfc 輸出.sfc
```

- 需要 Python 3，不需要安裝其他套件。
- `.smc` 的 512 字節檔頭會自動處理。
- 寫入前會檢查兩個修改點的原始位元組，以及 `$86:FFA0` 的空間是否未使用；不符就停止，不會改動檔案。
- 存檔格式不變，舊存檔可直接使用。
- 與其他補丁一起使用時，請確認對方沒有使用 `$86:FFA0–FFC5`，也沒有修改 `$84:A649`、`$84:A69A`。

`make_ips.py` 可由原版與修正版產生 IPS：`python3 make_ips.py 原版.sfc 修正版.sfc 輸出.ips`。

## 已知範圍與限制

- 只修正升級時的血統成長加成。`$84:A5C0` 另有 4 個呼叫點（`$80:BCB4`、`$84:A0BA`、`$84:F695`、`$89:90C2`，用於狀態畫面、戰鬥數值等），理論上也可能被 NMI 干擾，但本次未觀察到、也未修正。
- 其他以 `$00–$0F` 為暫存、橫跨多幀執行的程式，可能有同樣問題；本次只檢查了升級路徑。
- 統計樣本來自單一角色（霍林）、單一存檔、低勝率對戰。其他角色、其他鬥技場與地圖戰鬥的發生率未量測。
- **未在 SNES 實機上測試。** 只在 snes9x 核心、SuperZSNES 模擬器與自製 65816 模擬器上執行過。日文原版 IPS 在 snes9x 確認可正常開機進入片頭；中文版（搭配其他個人補丁）完成 161 場重播，並在 SuperZSNES 中實際遊玩多個回合。
- 未測試英文漢化版。腳本寫入前會先檢查位元組，不相容時會拒絕套用，不會寫壞 ROM。歡迎回報。

## 網路傳言的判定

| 傳言 | 判定 |
|---|---|
| 在鬥技場升級，成長常常比正常還差 | **對**。原因是本錯誤，不是鬥技場有特別規則。 |
| 就算 100% 的能力也可能不加 | **對，但少見**。加成被覆寫成很大的負數時發生；161 次實測中 HP 未出現。 |
| 最後一擊時先按 B 中斷、選擇繼續再打完，就會用正常機率 | **對，但時機要準**。按 B 時，主人會問要脫離、繼續還是更換武器，選繼續會從中斷的回合接著打。用同樣 161 場實測：在最後一輪交手前中斷，結果與修正版逐場完全相同（161/161）；提早約 2.5 秒中斷只有部分效果（守備 23%），提早約 5 秒則完全沒有效果。原因：戰鬥動畫進行中，NMI 每幀佔掉 262 條掃描線中約 190 條，並且會用到 `$00–$03`，升級計算因此拖成 2～3 幀而被打斷；剛恢復時動畫還沒重新開始，NMI 約 4 條掃描線就結束、不碰 `$00–$03`，升級計算不到一幀就完成（在加了記錄點的 ROM 上實測：166 對 561 條掃描線）。戰鬥長短本身沒有影響（相關係數 −0.07）。 |
